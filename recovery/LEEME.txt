BOT FRAMEWORK: RECONSTRUCCIÓN SOBRE EL FLUJO DE MAIN

La rama develop conserva la lógica del paquete publicado
A360EntaBotFramework-1.0.2-20260925-171647.jar y usa la estructura de origin/main
fd8a8e4: anotaciones del SDK, procesamiento de anotaciones, commandCodeGen y Shadow.
El inventario conserva el hash del paquete usado como referencia.

VERSION DE PRUEBA: 1.0.4
Esta versión reemplaza la reconstrucción provisional 1.0.3.

BUILD
Requiere JDK 11, JAVA_HOME y el wrapper de Gradle 7.6.2:
  ./gradlew clean build
En Windows:
  gradlew.bat clean build

Paquete final para Control Room:
  build/libs/A360EntaBotFramework-1.0.4.jar
El archivo con sufijo -thin es el JAR Java sin dependencias; no es el paquete
para importar. packageVersion/codeVersion reciben el timestamp generado por
el SDK, igual que en main.

FUENTES Y GENERACIÓN
src/main/java contiene 46 fuentes propias. Las clases de acción usan
@BotCommand, @CommandPkg, @Execute y las anotaciones de sus parámetros.
La condición usa @ConditionTest. Se recuperaron también las anotaciones de
campos inyectados, documentación y contexto global de sesión.

Los adaptadores *Command y *Condition se generan únicamente dentro de
build/generated/sources/annotationProcessor/java/main. No se versionan.
package.json se genera dentro de build/resources/main desde package.template
y las anotaciones. No hay un package.json manual en src/main/resources.

Se usan las dependencias Maven y los SDK declarados en main. No se compila
contra el JAR perdido ni contra un paquete agregado de dependencias extraídas.
Shadow reubica commons-io y conserva la configuración JDBC del proyecto.

RECUPERACIÓN
Las cuatro acciones ausentes de main son FileToBase64, AddItemAdvanced,
GetLastItem y UpsertItemDataField. Sus anotaciones se reconstruyeron a partir
del contrato del paquete publicado. Para las existentes se restauraron las
anotaciones originales de main, ajustándolas al contrato del JAR.

Se mantienen las diferencias reales del build perdido, entre ellas:
- StringToNumberSmart recibe amount, sin decimalPlaces.
- DeferWorkItem recibe ZonedDateTime en deferUntil.
- WorkqueueItemDao incluye getLastItem y las operaciones upsert.
- ItemDataTxnBuffer incluye addUpsert.
El texto de CopyFile se corrigió para no mencionar el parámetro inexistente
useSourceName. Sus nombres, tipos, validaciones y valores por defecto no cambian.

Se conservó código original de main donde su bytecode coincide con el publicado;
las demás implementaciones se reconstruyeron del JAR. No se recuperan todos los
comentarios ni se afirma que el texto sea idéntico al código fuente perdido.

VALIDACIÓN
- Los tests de main vuelven a src/test y se ejecutan con TestNG.
- Dos pruebas de fecha de creación comprueban primero que el sistema de archivos
  permite modificar creationTime; en caso contrario quedan omitidas. Deben
  ejecutarse en un sistema compatible para verificar ese comportamiento.
- RecoveredCommandsTest ejercita adaptadores generados desde las anotaciones.
- smokeTest ejecuta 20 comprobaciones sobre el JAR final.
- verifyPackage compara los 32 comandos y la condición con package-original.json,
  y verifica las clases y recursos recuperados. Solo admite la corrección de texto
  documentada para CopyFile.

Los resultados del build actual se registran en validacion-develop.json.
