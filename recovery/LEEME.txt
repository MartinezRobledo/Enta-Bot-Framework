BOT FRAMEWORK: MAIN ORIGINAL + DIFERENCIAS RECUPERADAS

BASE Y RESPALDO
Se apartó la reconstrucción develop 36ce702 en la carpeta hermana
Enta-Bot-Framework-reconstruido-36ce702, junto con su paquete 1.0.4.
Después se restauró el contenido de develop desde origin/main fd8a8e4 y se
comprobó que coincidiera exactamente antes de aplicar las diferencias.

De los 42 archivos Java originales de main, 35 permanecen idénticos byte por
byte, incluidos comentarios, espacios, saltos de línea e imports.
Se agregaron las cuatro acciones que no existían en main:
- FileToBase64
- AddItemAdvanced
- GetLastItem
- UpsertItemDataField

CAMBIOS PUNTUALES EN ARCHIVOS EXISTENTES
- StringToNumberSmart: firma con amount únicamente y NumberValue sin redondeo
  configurable. El parser original de main permanece sin modificaciones.
- CopyFile: criterio de carpeta por flag o directorio existente y estructura
  de parámetros del paquete recuperado. Se conserva el resto de main.
- RemoveDuplicatesFromList: retorno LIST, etiqueta e icono del paquete recuperado;
  la implementación original permanece sin modificaciones.
- CommitItemDataChanges: llama a upsertDataFieldsById/Key para aplicar staging.
- DeferWorkItem: recibe ZonedDateTime y lo convierte a Timestamp. Se conserva
  el helper anterior de main aunque ya no se utiliza.
- ItemDataTxnBuffer: agrega addUpsert, manteniendo los métodos originales.
- WorkqueueItemDao: agrega getLastItem y los dos upsert; aplica las diferencias
  recuperadas de diferimiento. Los demás métodos originales no se reemplazaron.
Los métodos nuevos usan las constantes SQL y el estilo de los métodos de main.

BUILD
Versión de prueba: 1.0.5. Con JDK 11 y JAVA_HOME:
  ./gradlew clean build
En Windows:
  gradlew.bat clean build

Paquete para importar:
  build/libs/A360EntaBotFramework-1.0.5.jar
El JAR -thin no es el paquete final. El SDK genera automáticamente adaptadores
Command y package.json bajo build/. Se mantienen las dependencias Maven,
commandCodeGen y Shadow de main. Las tareas agregadas verifican el contrato,
ejecutan TestNG y las comprobaciones de recuperación.

PRUEBAS
Se conservan los tests originales de main. El único cambio en un test existente
es la detección de soporte para modificar creationTime antes de los dos casos
que lo necesitan; se omiten cuando el sistema no lo permite.
Se agregan las comprobaciones recuperadas y pruebas de comandos generados.
WorkqueueDeltaTest comprueba getLastItem, upsert mixto (actualizar e insertar)
y commit de staging con una base Access temporal. Ese fixture configura
Jackcess con dateTimeType=LOCAL_DATE_TIME para las fechas de Java 11.
El build final se registra en validacion-develop.json.

INCIDENCIAS PREEXISTENTES IDENTIFICADAS AL COMPARAR
Se conservaron para no agregar cambios funcionales ajenos al trasplante:
1. deferFromWorkingByKey tiene seis parámetros SQL y asigna cinco valores.
2. Los upsert ejecutan ambos batches aunque uno esté vacío; UCanAccess 5.0.1
   falla con "statement is not in batch mode" cuando no hay campos nuevos
   que insertar. Se observó al probar una actualización sin inserciones.
Las pruebas positivas de upsert cubren una combinación de campos existentes
más campos nuevos. No acreditan el caso que presenta la incidencia anterior.
